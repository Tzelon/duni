🌬️What is Air?

Air ("Analyzed IR") is the output of Sema and the input to WatGen. It is a flat list of typed instructions — the program after semantic analysis, with every type resolved and every comptime-known value already interned. Unlike DIR (one instance per source file), each function gets its own Air.

💡

Key insight: an Air instruction's operand is never a value or a pointer — it is a Ref, a single u32 that means either "an interned constant" or "the result of another instruction". The whole file is really about how that one integer is packed and unpacked.

🗺️Big Picture

Text → Scanner → Parse → Ast → AstGen → Dir → Sema → Air → WatGen

Sema builds Air by appending instructions; WatGen reads Air to emit WAT. The InternPool lives beside both — Air never stores a constant inline, it stores an InternPool.Index disguised as a Ref.

🗄️Fields

The struct is tiny — two arrays:

FieldTypeRole
instructions MultiArrayList(Inst).Slice The instruction stream. Struct-of-arrays: a tag: Tag array and a data: Data array. A slot's position is its Inst.Index.
extra ArrayList(u32) Flat u32 overflow, for instructions whose payload doesn't fit in 8 bytes (e.g. call's trailing argument Refs). Indexed by a payload offset.

deinit frees both arrays. There is no separate value store — values are the InternPool's job, and Air only holds references to them.

🎭The two id types: Index vs Ref

Both are enum(u32). Both use bit 31 as a tag bit. The trick is they tag it differently, so the same instruction number lives under a different tag bit in each space. "Unwrap" / "convert to ref" is nothing more than reading or flipping that top bit — no allocation, no lookup.

Ref — "WHAT is this operand?"

A value slot. Polymorphic: an InternPool.Index (a constant/type) or an Air instruction's result.

bit31 = 0InternPool value bit31 = 1Air instruction 0xFFFFFFFFnone — bit31=1 but means IP's none
Index — "WHICH instruction slot?"

An identity: the key into instructions. Can only ever be an instruction.

bit31 = 0normal Air instruction bit31 = 1"target" pseudo-instruction
⚠️

The inversion is the whole point. For a real instruction #5, a Ref has bit31 = 1 but an Index has bit31 = 0. Because the same number sits under opposite tag bits, a conversion function has to exist to move between the two encodings.

📌

The target arm exists in unwrap for backend-invented pseudo instructions, but Duni has no producer for it yet — today every real Index has bit31 = 0.

🔓Index.unwrap → convert to Ref

unwrap sorts a raw Index into "convertible-to-Ref" vs "target pseudo-instr". It strips the tag bit to get the number, then reads the tag bit to decide: 

pub fn unwrap(index: Index) union(enum) { ref: Inst.Ref, target: u31 } {
    const low_index: u31 = @truncate(@intFromEnum(index));        // strip tag bit
    return switch (@as(u1, @intCast(@intFromEnum(index) >> 31))) { // read tag bit
        0 => .{ .ref    = @enumFromInt(@as(u32, 1 << 31) | low_index) }, // normal → set T=1
        1 => .{ .target = low_index },                          // target → keep number
    };
}

pub fn toRef(index: Index) Inst.Ref {
    return index.unwrap().ref;   // only valid for a normal (T=0) Index
}

So a normal Index becomes a Ref by turning the tag bit on. A target Index has no Ref — unwrap hands you the raw u31 instead. toRef is just the happy path of that.

🔍Ref decoders — going the other way

A Ref can be an instruction or an interned value, so it has two "which kind is it?" queries. Both return ? — null means "not that kind". That null-check is a feature: it forces the constant case to be handled. 

pub fn toIndexAllowNone(ref: Ref) ?Index {
    return switch (ref) {
        .none => null,
        else => if (@intFromEnum(ref) >> 31 != 0)   // T=1 → it's an instruction
            @enumFromInt(@as(u31, @truncate(@intFromEnum(ref))))
        else null,                                    // T=0 → it's a value, not an instr
    };
}

pub fn toInternedAllowNone(ref: Ref) ?InternPool.Index {
    return switch (ref) {
        .none => .none,                              // special-cased FIRST
        else => if (@intFromEnum(ref) >> 31 == 0)   // T=0 → it's an IP value
            @enumFromInt(@as(u31, @truncate(@intFromEnum(ref))))
        else null,                                    // T=1 → it's an instruction
    };
}

The non-AllowNone variants (toIndex, toInterned) just assert(ref != .none) first, then delegate. And fromInterned goes the reverse — it copies an IP index verbatim and asserts its top bit is already 0: 

pub fn fromInterned(ip_index: InternPool.Index) Ref {
    return switch (ip_index) {
        .none => .none,
        else => {
            assert(@intFromEnum(ip_index) >> 31 == 0);   // guarantees T=0, doesn't set it
            return @enumFromInt(@as(u31, @intCast(@intFromEnum(ip_index))));
        },
    };
}
✅

Why the static Refs are bit-identical to IP indices. comptime_int_type, f64_type, zero … are declared as = @intFromEnum(InternPool.Index.xxx). Because a T=0 Ref is its InternPool index, fromInterned/toInterned are pure tag-bit checks, not table lookups. The order mirrors InternPool.Index exactly — change one, change both.

✍️Who sets the tag bit?

Nobody sets it by hand for the common cases — it falls out of which constructor you go through.

ProducerWhereTag bit
normal instr Index Sema — instructions.len 0 — implicit; a small count naturally has bit31=0
Index → Ref unwrap / toRef 1 — EXPLICIT: 1<<31 | n. This is the setter.
IP value → Ref fromInterned 0 — guaranteed by InternPool, asserted (not set)
none comptime constant 1 — 0xFFFFFFFF; special-cased before the tag bit is ever read

So for runtime operands, Index.unwrap/toRef is the code that stamps the 1. The 0 for interned values is never stamped — it's an invariant of InternPool (it never hands out an index ≥ 2³¹) that the conversion merely asserts.

🤔Why two types — why convert at all?

You never "move" an instruction; it stays in the array. You switch between two ways of talking about it, because Sema builds a graph where the two roles are genuinely different — and one of them (Ref) also has to cover constants.

Index → Ref  (at the use site)

"I made an instruction, now feed its result to another." Cheap, total, always valid. Every %N in an operand position is a Ref that started as an Index.

%5 = load(ptr)       // Index(5)
%6 = load(ptr2)      // Index(6)
%7 = add(%5.toRef(),
        %6.toRef())  // add's operands are Refs
Ref → Index  (at the consume site)

"I got an operand; tell me about the instruction behind it." Partial (?Index) — the operand might be a constant, and the null forces you to handle that.

if (ref.toInterned()) |ip| ...  // a constant
else {
    const idx = ref.toIndex().?;  // an instr
    // index instructions[idx]
}

The payoffs of keeping them distinct, all visible in this file:

  • Type-level guarantees. An operation that only makes sense on a real instruction takes an Index in its signature — "this can't be a constant" is a compile error, not a runtime crash.
  • Array indexing without masking. A normal Index has bit31=0, so its bits are the slot number — index instructions directly. The same instruction as a Ref has bit31=1 and would need masking on every access.
  • Legible intent. A field typed Index says "an instruction I will inspect/patch"; one typed Ref says "a value that could be anything".

🧩Inst & Tag

An Inst is a tag: Tag + data: Data. Tag is a one-byte discriminant that says which Data field is active and how to read it. Only two tags exist today:

TagData fieldMeaning
ret un_op Return a value from a function. un_op is the returned Ref.
call pl_op Function call. operand is the callee Ref; payload indexes a Call record in extra, followed by one trailing Ref per argument (args_len). Result type is the callee's return type.
💡

Call is struct { args_len: u32 } with a trailing list of Inst.Ref. This is the same "fixed header + trailing slice in extra" pattern the AST and DIR use for variable-length data.

🏷️typeOf — reading a Ref's type

typeOf is the canonical place the Ref decode branch shows up. Given any operand Ref, first ask "is it a constant?" — if so its type comes from the InternPool; otherwise it's an instruction and its type comes from the instruction. 

pub fn typeOf(air: *const Air, inst: Inst.Ref, ip: *const InternPool) Type {
    if (inst.toInterned()) |ip_index| {          // T=0 → a constant/type
        return .fromInterned(ip.typeOf(ip_index));
    } else {                                     // T=1 → an instruction
        return air.typeOfIndex(inst.toIndex().?, ip);
    }
}

typeOfIndex then switches on the instruction's tag. call resolves the callee's type and returns its function return type; ret is unreachable (it produces no value).

🎬Worked example — round-tripping instruction #5

Sema emits an instruction

It appends to instructions; the new slot number is len - 1 = 5. As an Index that's 0x0000_0005 (bit31 = 0, for free).

Wire it into another instruction

Index(5).toRef() → unwrap sees T=0 → 1<<31 | 5 = 0x8000_0005. Now it's a Ref tagged "instruction", ready to sit in an operand slot.

A consumer reads that operand

ref.toInterned() → bit31 is 1 → null ("not a constant"). So it asks ref.toIndex() → bit31 is 1 → take low 31 bits → Index(5). Round-trips.

Contrast: a constant operand

If the operand were f64_type (0x0000_0002, bit31 = 0), toInterned() returns InternPool.Index(2) immediately and toIndex() returns null — no instruction behind it.

🧠

Mental model: Ref = tagged union of {InternPool value | instruction}; Index = tagged union of {normal instruction | target instruction}. "Unwrap" reads the tag bit; "convert to ref" moves the instruction number into Ref's encoding by turning the tag bit on. Pure bit twiddling.
