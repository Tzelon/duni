📦What is the InternPool?

The InternPool is a deduplicating value store used during semantic analysis. Its job is simple: every typed value in the compiler (integers, floats, types) gets assigned a stable integer index. Two values that are equal always get the same index, so equality checks become a single integer comparison.

💡

Key insight: once a value is interned, you never compare values directly again — you compare Index integers. a == b tells you whether the values are identical, regardless of how they were originally stored.

It is owned by main.zig and threaded through Sema and WatGen. All stages read and write to the same pool.

🗺️Big Picture

The InternPool sits in the middle of the compiler pipeline:

Text → Scanner → Parse → Ast → AstGen → Dir → Sema ← InternPool → Air → WatGen

The pool does two separate things, each with its own storage:

Value interning

Stores typed values (ints, floats, types). Returns an Index. Three backing arrays: items, extra, limbs.

String interning

Stores UTF-8 strings. Returns a NullTerminatedString index. Three backing arrays: string_bytes, strings, string_map.

🗄️Fields

The struct has six fields. Here's what each one is for:

Field Type Role
items MultiArrayList(Item) The main packed array. Every interned value is one slot here — a tag byte and a data: u32. The slot's array position is its Index.
map HashMapUnmanaged(Index, void) The dedup guard. Maps an Index → nothing (we only need the key). The Adapter trick lets us query it with a Key without inserting first.
extra ArrayList(u32) Flat u32 array for structured overflow. Floats (and future compound types) store their data here as a sequence of u32 fields.
limbs ArrayList(Limb) Storage for arbitrary-precision integers. Big ints are stored as a header (Int packed struct) followed by the raw limbs.
string_bytes ArrayListUnmanaged(u8) Flat byte buffer. All interned strings are appended here back-to-back, each null-terminated.
strings ArrayListUnmanaged(u32) Offset table. strings[i] is the byte offset of the end of string i (one past its null byte). Subtract the previous entry to find the start.

🔢Index enum

Index is a u32-backed enum. Its numeric value is the slot number inside items. The first few values are statically pre-allocated so every file in the compiler can refer to them by name without calling get().

0 comptime_int_type the type itself
1 comptime_float_type the type itself
2 f64_type the type itself
3 string_type the type itself
4 zero 0 (comptime_int)
5 one 1 (comptime_int)
6 negative_one −1 (comptime_int)
7+ runtime values added by get()
2³²−1 none sentinel / "no value"
⚠️

Order matters. The static indices are assigned by position in static_keys, not by name. Adding an entry to Index or static_keys shifts all subsequent values. Simple types must stay the leading contiguous block — indexToKey decodes them positionally — which is why string_type was inserted before zero, shifting the value statics by one. Dir.Inst.Ref mirrors this order positionally and Air.Inst.Ref by explicit value; all four places move together.

🔑Key union

A Key is the logical description of a value — what you hand to get() to look something up or insert it. It is not stored directly; it is only used for hashing and comparison, then discarded. The pool stores a more compact encoded form.

Variants

simple_type

One of comptime_int, comptime_float, f64, string. Stored as just the enum tag — no data needed because the Index value itself encodes which type.

int

An integer value. Has two parts:

ty the type index (currently only comptime_int_type) storage one of .u64, .i64, or .big_int
✅

Storage variants are equivalent. u64{42}, i64{42}, and a single-limb big_int of 42 all hash and compare as the same value. Canonicalization is done via toBigInt() in the hash function.

float

A floating-point value. Has:

ty comptime_float_type or f64_type storage .f64 = f64 — bit-exact comparison (NaN ≠ NaN)
string

A string value. The payload is a single NullTerminatedString — the handle the byte-interning layer (getString) returned for the bytes. No type field: all strings are string_type.

✅

Equality is handle equality. getString dedupes the bytes before a Key ever exists, so equal strings share one handle — hash64/eql compare the handle, never the bytes. Do not "fix" them to compare bytes.

🏷️Tag enum

The Tag is a one-byte discriminant stored alongside every item in items. It tells you how to interpret the 32-bit data field next to it.

Tag data field means Notes
simple_type 0 (unused) The Index value itself identifies the type via the SimpleType enum cast.
int_comptime_int_u32 integer value (fits in u32) Fast path for small non-negative comptime ints.
int_comptime_int_i32 integer value, bitcast u32 Fast path for small negative comptime ints (e.g. −1).
int_u32 / int_i32 — Reserved for future concrete integer types (not yet used — unreachable in indexToKey).
int_positive index into limbs Positive big integer. Limbs array starts with an Int header, then raw Limb words.
int_negative index into limbs Same layout as int_positive but the sign is negative.
float_f64 index into extra An f64 value split into two u32 pieces (Float64 struct).
float_comptime_float index into extra Same encoding as float_f64, different type.
string NullTerminatedString handle A string value. The handle fits directly in data — no extra record; length comes from the strings offset table.

// Packing a 64-bit float for storage in extra
fn pack(val: f64) Float64 {
    const bits: u64 = @bitCast(val);
    return .{
        .piece0 = @truncate(bits),          // bits[0..31]
        .piece1 = @truncate(bits >> 32),    // bits[32..63]
    };
}

Header size: Int is a packed struct of two u32 fields. On 64-bit targets a Limb is u64, so the header occupies exactly one limb slot (limbs_items_len = @sizeOf(Int) / @sizeOf(Limb) = 8/8 = 1). On 32-bit targets a limb is 32 bits wide, so the header takes two slots.

To read a big int back, indexToKeyBigInt does:

// data field from items holds the start index into limbs
const int: Int = @bitCast(ip.limbs.items[limb_index..][0..Int.limbs_items_len].*);
const big_int: BigIntConst = .{
    .limbs = ip.limbs.items[limb_index + Int.limbs_items_len ..][0..int.limbs_len],
    .positive = positive,  // comes from the tag (int_positive / int_negative)
};

NullTerminatedString is a u32-backed enum. Its value is the index into strings, not into string_bytes. To get the actual bytes for string i: 

// start of string i = end of string (i-1) = strings[i]
// end of string i = strings[i+1] - 1  (excluding null terminator)
const start = ip.strings.items[@intFromEnum(s)];
const end   = ip.strings.items[@intFromEnum(s) + 1] - 1; // strip '\0'
return ip.string_bytes.items[start..end];
🌱

Why seed with 0? init() appends a 0 to strings before interning anything. This means strings[0] = 0 is the start-of-buffer anchor, and string index 0 is always the empty string "" (which occupies byte 0 = '\0').

🚀init — Seeding static values

Before any user code can intern values, init() populates the pool with the statically-known entries. It loops over static_keys (an array of Key) and calls get() for each one, asserting the resulting index matches the corresponding Index enum value.

Seed the strings offset table

Append 0 to strings, making entry 0 the "start-of-buffer" anchor.

Intern the empty string ""

This becomes NullTerminatedString.empty at index 0.

Intern all static_strings

Identifier names used by the compiler (from string.zig) get stable numeric indices.

Intern all static_keys

The seven pre-defined types and values (indices 0–6) are inserted in exact order and asserted against their expected Index names.

🔍get — Interning a value

get(key) is the hot path. It either returns an existing Index or encodes the key and inserts a new item.

Reserve a candidate index

new_index = items.len — the slot that would be used if this is a new value. Also pre-allocate one item slot.

Probe the hash map

map.getOrPutContextAdapted(key, adapter, ctx) hashes the Key and looks for a match. If found, return the existing index immediately — no allocation.

Encode the value

Pick the most compact representation: small comptime ints → int_comptime_int_u32/i32; large ints → limbs; floats → extra.

Commit

Store new_index as the map entry's key, return it. Future calls with equal values will hit step 2 instead.

Integer encoding decision tree

if ty == comptime_int_type {
    // Try 32-bit fast paths first
    if fits_u32(value)  → tag = int_comptime_int_u32,  data = value
    if fits_i32(value)  → tag = int_comptime_int_i32,  data = @bitCast(value)
}
// Fallback: store in limbs regardless of storage variant in the key
tag = int_positive / int_negative, data = limbs start index
💡

The fast paths check value range, not storage variant. Even if the caller supplies a .big_int key, if it fits in 32 bits it still takes the compact path. This keeps items small.

💬getString — Interning a string

Follows the same pattern as get() but operates on the string-specific arrays.

Candidate index

new_index = strings.len - 1 — the offset entry that will be written after the new string's bytes.

Probe string_map

The adapter compares byte slices. On a hit, return the existing NullTerminatedString.

Append bytes + null terminator

Copy slice into string_bytes, then append 0.

Append end-offset

Push string_bytes.len onto strings, marking where this string ends.

🧵String values — the value layer

Strings live in the pool twice, at two different layers doing two different jobs:

Byte layer — getString

Dedupes bytes. Returns a NullTerminatedString handle. Used for identifier names (AstGen scope lookups) and as the backing store below. Knows nothing about types or values.

Value layer — get(.{ .string = handle })

Wraps a handle as a first-class value of type string_type. Returns an Index — so a string constant joins the same universe as ints and floats: one slot in items, comparable by index, referencable from Air.

How Sema turns a DIR str instruction into an Air constant (dirStr):

Read the bytes from DIR

data.str.get(sema.code) — AstGen already copied the literal's bytes into the DIR's own string_bytes.

Intern the bytes

ip.getString(gpa, bytes) — dedup happens here, at the byte layer. Equal literals collapse to one handle.

Intern the value

ip.get(gpa, .{ .string = handle }) — because equal strings already share a handle, the map probe compares one u32.

Wrap as an Air ref

.fromInterned(index) — the constant now flows through Sema like any interned value.

💡

Why no {start, len} record? The handle is a row in the strings offset table, and the table's boundaries already carry the length — toSlice never scans for the terminator. One u32 in data is the whole encoding. (See notes/intern_pool.md, "String values — one handle type", for the full comparison with Zig's design.)

⚠️

Boundary of the arc: WatGen lowers a string-typed result as a (ptr, len) pair of i32s — the bytes go into a (data …) segment in linear memory (exported as "memory"), deduped by handle. String operators (concat, compare) are not yet in Sema — that's the remaining strings-arc work.

↩️indexToKey — Reading a value back

Given an Index, reconstruct a Key. This is the reverse of encoding and is used by the hash-map context to compare stored items.

Tag seenWhat indexToKey returns
simple_type Cast the Index integer to SimpleType, wrap in .simple_type.
int_comptime_int_u32 .int{ ty=comptime_int, storage=.u64{ data } }
int_comptime_int_i32 .int{ ty=comptime_int, storage=.i64{ @bitCast(data) } }
int_positive / int_negative Read header + limbs from limbs[data..] via indexToKeyBigInt. Then try to downcast to .u64 or .i64 before falling back to .big_int.
float_f64 / float_comptime_float Read Float64 from extra[data..], reassemble to f64, wrap in .float.
string .string = @enumFromInt(data) — the data field is the handle; nothing else to decode.

🔀Context & Adapter

Zig's hash maps support two-sided custom hashing. The InternPool uses this to enable looking up a Key without first converting it to an Index.

Context (stored side)

Operates on Index values already in the map. To hash or compare, it calls indexToKey(index) to get back the canonical Key, then delegates to Key.hash64 / Key.eql.

hash(index) → indexToKey(index).hash64(ip)
eql(a, b)   → Key.eql(indexToKey(a), indexToKey(b))
Adapter (probe side)

Operates on a Key you're looking up with. Used in getOrPutContextAdapted so you can search the map by Key before the item has been encoded or assigned an Index.

hash(key)        → key.hash64(ip)
eql(key, stored) → key.eql(indexToKey(stored), ip)

This is what makes the "check-then-insert" pattern allocation-free on cache hits: no encoding, no limb allocation, no extra slot — just a hash lookup.

📋Static keys

static_keys is a comptime array that declares the seven pre-interned values in the exact order they must appear in items: 

pub const static_keys: [static_len]Key = .{
    .{ .simple_type = .comptime_int  },    // Index 0 = comptime_int_type
    .{ .simple_type = .comptime_float },   // Index 1 = comptime_float_type
    .{ .simple_type = .f64           },    // Index 2 = f64_type
    .{ .simple_type = .string        },    // Index 3 = string_type
    .{ .int = .{ .ty = .comptime_int_type, .storage = .{ .u64 =  0 } } }, // Index 4 = zero
    .{ .int = .{ .ty = .comptime_int_type, .storage = .{ .u64 =  1 } } }, // Index 5 = one
    .{ .int = .{ .ty = .comptime_int_type, .storage = .{ .i64 = -1 } } }, // Index 6 = negative_one
};
